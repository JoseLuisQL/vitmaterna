# Cumplimiento ISO/IEC 25010 — VITMATERNA

> Modelo de calidad del producto software (ISO/IEC 25010:2011). Este documento
> evalúa el sistema VITMATERNA (backend Node/Express + Prisma/PostgreSQL/Redis;
> frontend Expo/React Native) frente a las **8 características** del modelo, con
> evidencia trazable en el código y las brechas pendientes.

Leyenda de estado: ✅ Cumplido · 🟡 Parcial · ⛔ Pendiente

---

## 1. Adecuación funcional (Functional Suitability)

| Subcaracterística | Estado | Evidencia |
|---|---|---|
| Completitud funcional | 🟡 | 10 módulos implementados (auth, gestantes, citas, tratamientos, clínico, educación, notificaciones, reportes, chat, administración). Funciones avanzadas añadidas: chatbot 24/7, mensajes masivos, aviso al acompañante, tamizajes SRQ-18/violencia. Pendientes: modo offline avanzado y quechua. |
| Corrección funcional | ✅ | Cálculos críticos (IMC, EG, FPP por Naegele, corrección de Hb por altitud MINSA, semáforo de riesgo) con **pruebas unitarias** (`backend/tests/unit/`, 34 casos). |
| Pertinencia funcional | ✅ | Requisitos derivados de historia clínica real y protocolo MINSA (`implementation_plan.md`, `prd.md`). |

**Evidencia ejecutable:** `npm test` (backend) → 44 pruebas; `scripts/smoke-test.mjs` → 30 endpoints.

## 5. Fiabilidad (Reliability)

| Subcaracterística | Estado | Evidencia |
|---|---|---|
| Madurez | ✅ | 64 pruebas automatizadas (44 backend + 20 frontend); manejo centralizado de errores (`errorHandler.middleware.ts`). |
| Disponibilidad | 🟡 | Healthcheck (`/health`); reintentos en cliente (React Query). Despliegue HA y monitoreo formal pendientes. |

| Capacidad de recuperación | 🟡 | Backup manual (`/admin/backup`). Respaldo automático y RTO/RPO formal pendientes. |

## 6. Seguridad (Security)

| Subcaracterística | Estado | Evidencia |
|---|---|---|
| Confidencialidad | ✅ | Contraseñas con bcrypt (12 rounds); JWT de acceso/refresh; datos sensibles tras autenticación. |
| Integridad | ✅ | RBAC por rol (`rbac.middleware.ts`), validación de entrada (Zod), restricciones en BD. Probado: gestante recibe 403 en endpoints de obstetra. |
| No repudio | ✅ | Auditoría de acciones (`audit.middleware.ts`, `/admin/audit-logs`). |
| Responsabilidad (accountability) | ✅ | Logs con `userId`, request-id y timestamp (pino). |
| Autenticidad | ✅ | Bloqueo por intentos fallidos (5/15 min) y rate limiting (`rateLimiter.middleware.ts`). |

**Brechas:** cifrado en reposo a nivel app (AES-256) y consentimiento Ley 29733 a reforzar.

### Brechas priorizadas para cierre completo
1. Modo offline + sincronización robusta (RNF-2.02).
2. Cifrado en reposo (AES-256) y refuerzo de consentimiento (Ley 29733).
3. Backup automático con RTO/RPO definidos.
4. Integración HIS/SIS del MINSA e indicadores ENDES completos.
5. Multi-tenant para replicación en otros establecimientos.
6. Caché de reportes agregados.
